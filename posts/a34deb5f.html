Part I. 怎么 Hash

一、关于 hash

哈希的本质思想：映射。对于非整数对象，或者对于很大的整数值域，将其映射到一个较小的值域空间。这样就能用数表示，方便比较或用数组存储。

哈希冲突：两个东西映射到了同一个数。

二、Hash 表

可能存在的问题 (hack)

  1. std::unordered 家族

如 unordered_set、unordered_multiset、unordered_map 都是使用哈希实现的，可以被特定数据卡掉。

unordered_map 在 GCC 的实现中是维护了一个桶，每个桶对应一条单链表。正常情况下，哈希函数将元素均匀分散到不同的桶中，此时查找、插入、删除的平均复杂度为 O(1)O(1)O(1)。

GCC 的默认哈希函数是直接取模。只需要翻到这个固定的素数表，取这个素数的倍数，取模后的桶索引就恒等于 0。这样，它们就会全部塞进同一个桶里，后续每次都需要遍历这个桶的整个链表，总复杂度退化到 O(N2)O(N^2)O(N2)，从而 TLE。

  1. pbds

在 __gnu_pbds 中，有两种哈希表：

  • __gnu_pbds::cc_hash_table：cc 拉链法解决哈希冲突，和 umap 没什么区别，甚至更慢。
  • __gnu_pbds::gp_hash_table：gp 探查法解决哈希冲突，当发生哈希冲突时，通过探测在数组中向后寻找空位，相比于 umap，更快，代价是空间复杂度略大。hack 方法：桶的数量是 2k2^k2k，构造一组末尾 kkk 位二进制全部为 0 的数据，哈希索引都会恒等于 0。

解决方案

  1. 换 map：多个 log，看时间能否接受。
  2. 确定性方法 ：能想到可以用，想不到就没必要了（废话。
  3. SplitMix64：一个安全的自定义哈希函数，见下。

Part II. Hash 什么

设 HHH 表示随机底数，H(x)H(x)H(x) 表示随机的哈希函数，PPP 表示大素数。

一般情况，hash 对象都可以转化为 f(H) mod Pf(H) \bmod Pf(H)modP，现举数例如下。

一、多重集合

随机一个哈希函数 H(x)H(x)H(x)，取

f(S)=∑x∈SH(x) mod 264f(S) = \sum_{x \in S} H(x) \bmod 2^{64}f(S)=x∈S∑​H(x)mod264

令 cxc_xcx​ 是两个集合中元素 xxx 的出现次数之差，碰撞概率为 2−(64−min⁡ν2(cx))2^{-(64-\min \nu_{2}(c_x))}2−(64−minν2​(cx​))。说人话就是如果所有的数的出现次数都包含 2 的幂次，低位就无效，更容易碰撞。

若选用  mod P\bmod PmodP，碰撞概率为 1P\dfrac{1}{P}P1​。

二、不重集合

采用 xor-hash，随机一个哈希函数 H(x)H(x)H(x)，取

f(S)=⨁x∈SH(x) mod 264f(S) = \bigoplus_{x \in S} H(x) \bmod 2^{64}f(S)=x∈S⨁​H(x)mod264

或采用上述多重集 hash 方法。

应用：

  • 区间染色问题，如 CF1996G
  • 判定图的边子集是否为图的一个割

三、多项式 / 幂级数

直接取这个多项式为 hash 函数，即随机一个哈希值 HHH，代入 f(H) mod Pf(H) \bmod Pf(H)modP。

字符串 hash 本质是构造了一个多项式。

对于有根树，取

五、分数 / 大整数

（这个似乎鲜为人知）

将分数 pq\dfrac{p}{q}qp​ 映射为 p⋅q−1 mod Pp \cdot q^{-1} \bmod Pp⋅q−1modP，将大整数 nnn 映射为 n mod Pn \bmod PnmodP。其实是评测机判断概率准确的一种方法。

例题 ：已知 S=n!mS=\dfrac{n!}{m}S=mn!​ 及 1≤m<n≤1061 \le m < n \le 10^61≤m<n≤106，求 n,mn,mn,m。(2025 CCPC Harbin Practice A)

思路 ：选模数 PPP（至少满足 P>n, P>mP>n,\ P> mP>n, P>m，最好是 ULL 级别），在模意义下计算并验证。

实现 ：枚举 nnn，计算 m=n!S mod Pm=\dfrac{n!}{S} \bmod Pm=Sn!​modP。如果 m∈[1,n−1]m\in[1,n-1]m∈[1,n−1]，就说明找到了答案；否则说明此时 mmm 不是整数，不是答案。复杂度 O(log⁡S+nlog⁡P)\mathcal{O}(\log S + n \log P)O(logS+nlogP)。

正确性 ：对于一个枚举值 nnn，其对应的 n! mod Pn! \bmod Pn!modP 与 SSS 无关。因此，计算出的 m=(n!⋅S−1) mod Pm = (n! \cdot S^{-1}) \bmod Pm=(n!⋅S−1)modP 在区间 [0,P−1][0, P-1][0,P−1] 上可视为均匀分布，恰好落在合法区间 [1,n−1][1, n-1][1,n−1] 内的概率为 n−1P\dfrac{n - 1}{P}Pn−1​。遍历所有 n∈[2,106]n \in [2, 10^6]n∈[2,106] 时，整个算法期望出现的错误答案总个数 E=n2P=1012PE = \dfrac{n^{2}}{P} = \dfrac{10^{12}}{P}E=Pn2​=P1012​。可见 PPP 最好是 ULL 级别。
